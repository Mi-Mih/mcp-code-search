# 🚀 Установка code-search

Инструкция от нуля до работающего поиска. Всё локально, наружу ничего не уходит.

Что получится в итоге: у Клода появится инструмент `search_code`, который отвечает на
вопросы вида «где в коде инвалидируется кэш?» — то есть на вопросы, где вы **не
знаете, как искомое названо**. Зачем он нужен и чем отличается от Grep — в
[README.md](README.md); здесь только «что набрать».

**Времени:** минут двадцать вашего плюс сорок минут, пока считается индекс (можно
уйти пить чай). **Места на диске:** ~1.5 ГБ на модель и ~25 МБ на индекс проекта.

Каждый ставит себе сам: индекс считается на вашей машине и лежит внутри вашего
чекаута. Готовый индекс передать нельзя — он привязан к содержимому файлов.

---

## 0. ✅ Проверить, что подходит окружение

```bash
python3 --version                                     # нужен 3.10 или новее
python3 -c "import sqlite3; print(sqlite3.sqlite_version)"   # нужен 3.43 или новее
git --version
```

Питоновских зависимостей нет вообще — только стандартная библиотека. Ни venv, ни
`pip install` не понадобится.

Если SQLite старее 3.43 — дальше идти нельзя, индекс не соберётся (нужен
`contentless_delete`). Обычно достаточно обновить дистрибутив или взять Python
поновее: SQLite приезжает вместе с ним.

## 1. 🧠 Поставить Ollama и модель эмбеддингов

Ollama — локальный сервер моделей, он и будет считать векторы.

```bash
curl -fsSL https://ollama.com/install.sh | sh     # Linux
ollama pull bge-m3                                 # ~1.2 ГБ, качается один раз
```

На macOS и Windows берите установщик с [ollama.com/download](https://ollama.com/download).

Проверить, что живо:

```bash
curl -s http://127.0.0.1:11434/api/tags | head -c 200
```

Должен ответить JSON со списком моделей. Если молчит — поднимите вручную:
`ollama serve` (на Linux с systemd обычно уже запущен как сервис).

> **Если сайт Ollama не открывается.** У некоторых провайдеров он заблокирован.
> Вариантов два: скачать установщик и модель через VPN, либо попросить у коллеги,
> у кого уже стоит, каталог с моделью — на Linux это `~/.ollama/models`, его можно
> скопировать целиком. Сам Ollama при этом всё равно нужно установить.

## 2. 📦 Взять код

```bash
git clone <адрес репозитория code-search> ~/code-search
```

Ставить и собирать ничего не надо — сервер запускается прямо из каталога.
Запомните путь до каталога `code-search`, он понадобится дважды.

## 3. 🗂️ Собрать индекс

Это самый долгий шаг и делается он один раз.

```bash
cd ~/code-search
python3 -m code_search.indexer /путь/к/вашему/чекауту/проекта
```

**~40 минут** на проект в 60 тысяч строк. Скорость упирается в Ollama, не в код.
Прогресс печатается по файлам с оценкой остатка; каждый файл сохраняется отдельно,
поэтому прервать `Ctrl-C` и продолжить позже — безопасно, сделанное не потеряется.

Перед долгим прогоном полезно посмотреть, что вообще попадёт в индекс:

```bash
python3 -m code_search.indexer /путь/к/проекту --dry-run
```

Если увидите там вендоренные каталоги или чужой код — исключите:

```bash
python3 -m code_search.indexer /путь/к/проекту --exclude 'extern/*' --exclude 'airflow/*'
```

По умолчанию индексируются только `.py`, `.rst` и `.md`. Список файлов берётся у git:
отслеживаемые плюс неотслеживаемые, которые не попадают под `.gitignore` — то есть
ваши локальные черновики в индекс войдут, а venv и артефакты сборки нет.

Сколько файлов отброшено по расширению, `--dry-run` печатает отдельной строкой:

```
пропущено по расширению: 813 файл(ов) — .ts 402, .html 231, .scss 118, ...
```

Если у вас там половина проекта — добавьте эти расширения (флаг повторяемый):

```bash
python3 -m code_search.indexer /путь/к/проекту --suffix .ts --suffix .html
```
Такие файлы режутся обобщённо, по пустым строкам: парсера для них нет, поэтому
у фрагментов не будет ни имён функций, ни сигнатур, и находиться они будут хуже,
чем Python. Насколько хуже — никто не измерял, все числа в README получены на
питоновском проекте. Настройка запоминается в самом индексе, так что повторять
флаг при обновлениях не нужно; отказаться — `--suffix none`.

Результат кладётся в `<проект>/.code-search/` вместе с `.gitignore`, который его
прячет — в коммит он не попадёт.

Проверить, что получилось:

```bash
python3 -m code_search.search /путь/к/проекту "где инвалидируется кэш" -k 5
```

Должны увидеть пять фрагментов с путями и номерами строк. Если да — поиск работает,
осталось показать его Клоду.

## 4. 🔌 Подключить к Claude Code

Открыть `~/.claude.json` и добавить блок `mcpServers` внутрь записи вашего проекта.
Оба пути — абсолютные, без `~`.

```jsonc
{
  "projects": {
    "/путь/к/вашему/чекауту/проекта": {          // ← ровно тот каталог, из которого
      "mcpServers": {                             //   вы запускаете claude
        "code-search": {
          "command": "/usr/bin/python3",
          "args": [
            "-m", "code_search.server",
            "--root", "/путь/к/вашему/чекауту/проекта"
          ],
          "env": {
            "PYTHONPATH": "/путь/к/code-search",
            "PYTHONUTF8": "1"
          }
        }
      }
    }
  }
}
```

Три места, где легко ошибиться:

- **Ключ проекта должен совпадать с каталогом запуска Claude Code буквально.**
  Запустите `claude` из подкаталога — сервер не подхватится, и никакой ошибки вы
  не увидите. Если записи вашего проекта в файле ещё нет, добавьте её целиком.
- **Интерпретатор — абсолютным путём.** Claude Code запускает сервер не из вашей
  оболочки, и `python` в его `PATH` может не оказаться вовсе. Свой путь узнаете
  через `which python3`. На Windows это что-то вроде
  `"C:\\Python312\\python.exe"` — с двойными слэшами, как требует JSON.
- **`PYTHONPATH` — это каталог `code-search`,** тот, внутри которого лежит папка
  `code_search`. Не сама `code_search`.

Перед правкой сделайте копию: `cp ~/.claude.json ~/.claude.json.bak`.

Дальше перезапустите Claude Code **из каталога проекта** и наберите `/mcp`. Должен
быть `code-search` со статусом connected и двумя инструментами.

## 🔗 Другие клиенты: Cursor, Codex CLI

Сервер — обычный MCP поверх stdio, клиент может быть любым; индекс общий.
Команда запуска та же, различается только файл конфигурации.

**Cursor** — `.cursor/mcp.json` в корне проекта (или `~/.cursor/mcp.json`),
формат тот же, что у `.mcp.json`:

```json
{
  "mcpServers": {
    "code-search": {
      "command": "/usr/bin/python3",
      "args": ["-m", "code_search.server", "--root", "/путь/к/проекту"],
      "env": {
        "PYTHONPATH": "/путь/к/code-search",
        "PYTHONUTF8": "1"
      }
    }
  }
}
```

**Codex CLI** — `~/.codex/config.toml`:

```toml
[mcp_servers.code-search]
command = "/usr/bin/python3"
args = ["-m", "code_search.server", "--root", "/путь/к/проекту"]
env = { PYTHONPATH = "/путь/к/code-search", PYTHONUTF8 = "1" }
```

Требования на машине от клиента не зависят: Python 3.10+, SQLite 3.43+,
запущенная Ollama с `bge-m3`. Проверка без клиента — блок «Есть, но со статусом
failed» ниже: probe-команда оттуда работает с любым клиентом одинаково.

## 🔍 Как этим пользоваться

Инструмент рассчитан на вопросы, где вы не знаете имён в коде. Клод выбирает его сам,
специально спрашивать не надо — просто задавайте вопрос по-человечески:

- «где инвалидируется кэш»
- «где ограничивается размер входного файла»
- «в каких объектах хранится состояние между шагами»

**Когда он не нужен.** Знаете точное имя — лексический поиск (grep) быстрее и
точнее, и модель об этом предупреждена в описании инструмента. Замер: на точных
идентификаторах grep выдаёт медианно 4 файла, семантике там просто нечего добавить.

**Что заведомо не работает.** Вопросы про тесты («где тестируется расчёт расписания»)
— полнота 0.00, известный незакрытый провал. Там ищите через grep по имени модуля.

**Держать индекс свежим ничего не требует.** После ваших правок первый же поиск
заметит расхождение, ответит по имеющемуся индексу и допишет изменённое в фоне.
В выдаче при этом стоит `stale: true` — это рабочее состояние, а не ошибка.
Догоняет примерно за 10 секунд на изменённый файл.

Полная переиндексация нужна только если поменялась модель эмбеддингов или версия
нарезки — тогда сервер сам скажет, что индекс несовместим, и пересоберёт его.

## 🩺 Если что-то не работает

**В `/mcp` нет `code-search`.** Почти всегда — несовпадение ключа проекта в
`~/.claude.json` с каталогом, из которого запущен `claude`. Проверьте `pwd`.
Второе по частоте — сломанный JSON после правки: `python3 -m json.tool ~/.claude.json > /dev/null`.

**Есть, но со статусом failed.** Запустите сервер руками — так вы увидите ошибку,
которую Claude Code прячет:

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"index_status","arguments":{}}}' \
 | PYTHONPATH=/путь/к/code-search /usr/bin/python3 \
   -m code_search.server --root /путь/к/проекту
```

Первая строка — баннер в stderr, это нормально. Дальше должна быть строка JSON со
статистикой индекса.

**«Индекс не найден».** Шаг 3 не сделан, либо `--root` указывает не туда, куда
писал индексатор. Путь в обоих местах должен быть один и тот же.

**«Не удалось получить эмбеддинг запроса».** Ollama не отвечает. `ollama serve`,
затем проверьте `curl http://127.0.0.1:11434/api/tags`.

**Первый запрос думает три секунды, дальше — десятые доли.** Так и должно быть:
Ollama выгружает модель из памяти после простоя и поднимает её заново. Холодный
эмбеддинг — 2.7 с, тёплый — 0.09 с.

**Индексация идёт заметно дольше сорока минут.** Смотрите, сколько файлов взято
(`--dry-run`): скорее всего в индекс попал вендоренный код. Исключите его через
`--exclude` и пересоберите с `--rebuild`.

**Хочется начать заново.** `rm -rf <проект>/.code-search` — или тот же эффект через
`--rebuild`. Ничего, кроме индекса, там не лежит.

## 📝 Что стоит рассказать в ответ

Числа в README получены на одном проекте и одном наборе размеченных запросов. Если
у вас поиск ведёт себя иначе — это ценная информация, особенно два случая:

- Модель полезла в grep там, где явно нужен был `search_code` (или наоборот). Значит
  надо править описание инструмента — это единственное, что нельзя было проверить
  замерами.
- Нужный файл стабильно не попадает в первую десятку на каком-то классе вопросов.
  Один такой класс уже известен (тесты); если найдёте второй — его можно починить,
  но для этого нужны конкретные примеры вопросов и правильных ответов.
